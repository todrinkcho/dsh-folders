# 项目文件夹（@todrink/dsh-folders）

给 DeepSeek Harness Web GUI 加一个「桌面式项目文件夹」主面板：把真实目录画成文件夹网格，双击进入，
在文件夹里新建文件夹；任意目录都可以一键登记为工作区，直接打开工作区或它的会话。

## 它解决什么

- DSH 的工作区列表默认是平铺的；项目一多就找不过来。
- 这个插件提供一个独立的可视化「总文件夹」页面：文件夹卡片、面包屑、会话任务卡片。
- 文件夹就是磁盘上的真实目录，不引入第二套虚拟数据；登记工作区只调用官方 registry，不移动文件。

## 使用

1. 刷新页面（必要时重启 DSH），侧栏出现「项目文件夹」。
2. 打开后默认以所有已登记工作区的公共上级目录作为根目录；也可「选择根目录」。
3. 双击文件夹进入；「登记」把目录加入工作区；「打开工作区」新建/复用空白会话并进入对话。
4. 进入一个工作区后，下方列出它的会话，点击打开。
5. 「新建文件夹」创建目录（默认同时登记为工作区，可取消勾选）；「新建项目」创建目录并登记为工作区。
6. 想让侧栏本身按层级显示：点「整理侧栏」，把根目录/中间目录登记为工作区，然后在侧栏
   「视图选项 → 分组方式」选「按工作区树」。

## 外观

- 工作区画成带页签的彩色文件夹卡片，颜色按 workspaceId 哈希固定分配（8 色，不随排序变化）。
- 卡片显示名称、子工作区数、对话数；hover 抬升并带同色光晕。
- 进入工作区后，子工作区仍是文件夹卡片，对话变成独立卡片（状态点 / 运行中 / 空白 / 相对时间）。
- 页面整体可滚动；窄屏两列、`prefers-reduced-motion` 时关闭动效。

## 移动对话（可选增强）

装了 [`dsh-workspace-mover`](https://github.com/PianoPrince/dsh-workspace-mover) 之后，代码里的会话卡片会多出
**「移到…」**，文件夹卡片变成投放目标——这是"项目嵌套"最需要的能力：把对话在父/子文件夹之间搬来搬去。

- **按钮**：hover 对话卡片 → 「移到…」→ 选目标文件夹 → 看预检（可移动 / 原因 / 从哪到哪 / 备份大小）→ 「移动」。
- **拖拽**：直接拖对话卡片，丢到上方/下方的文件夹卡片上；文件夹会显示「松手即可移到这里」。
- **还没登记的目录**：对话框里点「登记其他文件夹并移入…」→ 在官方目录选择器里选目录（或输入路径 → 前往）
  → 「登记当前文件夹」→ 自动回到移动确认、目标已选好 → 点「移动」。一步完成"登记 + 搬入"。
- 只搬**对话记录**本身（日志、标题、归档/置顶状态），磁盘上的项目文件不动；搬完卡片立刻出现在新文件夹里。
- 搬运前 mover 会先备份到 `~\.dsh\workspace-mover\backups`（同内容复用），失败自动回滚；
  **正在跑任务的对话会被拒绝**，等它结束再搬。

没装 mover 时：面板一切照常，只是不出现「移到…」、卡片也不可拖。
（首次探测会向宿主问一次能力，控制台可能留一条 405 —— 预期行为，不影响使用。）

## 记忆开关提示（自动，无需配置）

搬动一条对话，会改变它记录的 `cwd`；而 `dsh-plugin-memory` 正是按 `cwd` 决定「这个项目要不要注入记忆」
（`disabledWorkspaces` 按路径边界匹配，父目录覆盖所有子目录）。所以搬进一个「默认关记忆」的文件夹后，
这条对话会悄悄不再注入记忆——看起来像插件坏了。

本插件在移动确认框里把这件事说清楚：

- 目标列表里，被 `disabledWorkspaces` 覆盖的文件夹右侧带一个 **「记忆关」** 标签；
- 选中后多一行：`目标记忆：关 ——「<命中的路径>」覆盖了这个目录（含子目录），搬过去后这条对话不再注入记忆`，
  并提示恢复办法（搬完在输入框的记忆开关里给这条对话单独打开，会话级开关优先级最高）；
- 记忆插件被全局关闭时，显示 `记忆插件已全局关闭，搬到哪里都不会注入记忆。`；
- 搬成功后的提示也会带上「（该文件夹默认关闭记忆）」。

怎么知道的：记忆插件不提供任何服务接口，所以本插件的 **Host 半区**只读 `<DSH_HOME>/memory.json`
（`enabled` + `disabledWorkspaces`），按它自己的规则（路径边界、`~` / `%USERPROFILE%` / `$HOME` 展开、
Windows 不分大小写）算一遍，再通过 `/folder-desktop` 同源 RPC 交给面板。

降级一律是「什么都不显示」，不会猜：文件不存在（没装记忆插件）、读不了、JSON 坏了、字段缺 → 面板上少一行而已。
本插件**绝不写** `memory.json`，也不读记忆内容。

## 边界

- 只读目录列表；创建目录走官方目录选择器；不移动、不改名、不删除已有文件。
- 宿主只提供系统原生目录选择器时，列目录/新建目录不可用，面板会提示。
- 会话仍由 DSH 管理；本插件只调用官方的打开/新建入口。
- 搬会话这件事**本插件不亲手改日志**：一律调用 `dsh-workspace-mover` 的同源 RPC（`mover.preview` / `mover.move`），
  失败与备份由它负责。所以 mover 是本插件唯一的外部依赖，且是**可选**的。
- 记忆开关提示只读 `<DSH_HOME>/memory.json`，不写、不改；`dsh-plugin-memory` 换配置文件名时提示会自动消失
  （降级，不是报错）。

## 开发

纯 JS、无构建。`client.js` 是浏览器半区（Module Loader 工厂，UI 全在这里）；
`index.js` 是 Host 半区，只做一件事：挂 `/folder-desktop` 同源 RPC，供面板查询目标文件夹的记忆开关状态。

```powershell
node --check client.js
node --check index.js
node E:\path\to\smoke-client.js client.js   # 见仓库外测试脚本，可选
```

Host 半区的独立自测（无需 DSH）：`_probe/memory-adapter-harness.mjs`（20 条断言，含父目录级联、
同前缀兄弟目录、`~` 展开、Windows 大小写、全局关闭、坏文件降级）。

## 安装 / 卸载

```powershell
# 安装（本机）
dsh plugin --profile web add <本包目录的绝对路径>

# 可选：解锁「移动对话」
dsh plugin --profile desktop add dsh-workspace-mover

# 卸载
dsh plugin --profile web remove @todrink/dsh-folders
```

卸载后浏览器 localStorage 里的 `dsh.folder-desktop.root.v1` 可手动清掉，不影响任何项目数据。
